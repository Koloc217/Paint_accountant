# Paint Catalog — план

Приложение для каталогизации красок для миниатюр: что есть, сколько банок, в какой коробке. Коробки помечаются NFC-метками (необязательно). Заносить краски можно по фото, без ручного набора.

Не привязано к брендам: справочник растёт из того, что пользователь занёс сам. Внешние каталоги — необязательный импорт для подсказок.

---

## Стек (предварительно)

- **Сервер:** Python, FastAPI, SQLite
- **Распознавание:** zxing-cpp (штрихкоды) + RapidOCR (текст), всё локально, без внешних AI API
- **Поиск по названию:** rapidfuzz (нечёткое совпадение)
- **Веб-интерфейс:** работает по http в локальной сети, без сертификатов
- **Telegram-бот:** заливка фото откуда угодно (бот сам ходит наружу, белый IP не нужен)
- **Тестовая машина:** Raspberry Pi 5 8GB — это стенд автора, а не требование проекта

---

## Платформы

Приложение не привязано к конкретному железу: должно одинаково запускаться на Linux (x86_64 и ARM64, включая Raspberry Pi) и Windows.

- Только кроссплатформенные зависимости, у которых есть готовые колёса (wheels) под Windows, Linux x86_64 и Linux ARM64 — ничего не собирать из исходников
- Пути к данным, БД и фото — через `pathlib`, без захардкоженных `/home/...`; место хранения задаётся в конфиге, по умолчанию `data/` в папке приложения
- Настройки (порт, адрес, токен бота, прокси) — в конфиг-файле / `.env`, никаких значений по умолчанию под конкретную машину
- Портативная раскладка: код, настройки (`config.ini`) и данные (`data/` — база и фото) лежат в одной папке приложения; ничего не ставится в систему через pip, только зависимости в venv
- Запуск одной командой `python run.py` на любой ОС; относительные пути считаются от папки приложения, а не от текущей директории
- Автозапуск — отдельные необязательные рецепты: systemd-юнит для Linux, планировщик задач (или служба) для Windows
- Распознавание (OCR, штрихкоды) — необязательный модуль: каталог должен работать и без него, если на какой-то платформе зависимости не встали
- Без системных утилит конкретной ОС (bash-скрипты, cron) в основной логике; фоновые задачи — внутри приложения
- Возможно позже: Docker-образ как ещё один способ установки, но не единственный

## Модель данных

### Краска (paint)
| поле | обязательное | примечание |
|---|---|---|
| id | скрытое | |
| название | да | |
| производитель | да | выбор из справочника производителей; новый можно добавить прямо из формы |
| код/артикул | нет | |
| штрихкод | нет | уникальный; запоминается при добавлении по фото |
| hex | нет | |
| теги | нет | несколько на краску |

### Где лежит (paint_location)
| поле | примечание |
|---|---|
| краска | |
| хранилище | пусто = без хранилища |
| количество банок | > 0; общее количество краски — сумма по хранилищам, 0 = «нет в наличии» |

### Производитель (manufacturer)
| поле | обязательное | примечание |
|---|---|---|
| id | скрытое | |
| название | да | уникальное без учёта регистра |

Стартовый список: AK, Citadel, Green Stuff World, Kaleido, Kimera, Tamiya, Vallejo. Производителя, у которого есть краски, удалить нельзя.

### Хранилище (storage)
| поле | обязательное | примечание |
|---|---|---|
| id | скрытое | |
| название | да | «Коробка 3», «Ящик у стола» |
| метка | нет | NFC/QR со ссылкой на страницу хранилища |
| под рукой | да, по умолчанию нет | ящик/органайзер в прямом доступе |
| по умолчанию | одно на всю базу | новые банки идут сюда; в новой базе это «Под рукой» |
| куда предлагать дубликаты | нет | хранилище, заранее выбранное в окне «добавить дубликат сюда или в другое хранилище» |

**Правила размещения банок:**
- при добавлении выбирается хранилище, по умолчанию подставлено хранилище по умолчанию; банки идут ровно туда;
- повторы (несколько банок одной краски) разрешены в любом хранилище;
- если хранилище «под рукой» и там эта краска уже есть (или кладут сразу несколько банок) → окно: «добавить сюда» или «в выбранное хранилище»; заранее выбрано хранилище из настройки «куда предлагать дубликаты»; проверка на сервере (`allow_duplicate`), так что работает и для бота;
- «переложить» — без вопросов;
- краска кладётся в хранилище, где её нет, а в другом месте она уже есть → предупреждение «уже есть в …»;
- −1 без указания хранилища берёт сначала из «под рукой»; если под рукой стало 0, а банки есть в другом месте → кнопка «Взять»;
- в общем списке — сумма по всем хранилищам.

### Тег (tag)
| поле | примечание |
|---|---|
| id | скрытое |
| название | |
| цвет плашки | |

Связь краска ↔ тег: многие-ко-многим.

**Стартовые теги** (редактируемые): Грунт, Основа, Слой, Контраст, Проливка, Спецэффект, Металлик, Чернила, Лак, Для аэрографа, Техническая (разбавители, медиумы, замедлители).

**Подсказка тегов по словам с этикетки** (небольшая таблица соответствий, дополняемая): Contrast → Контраст, Shade/Wash → Проливка, Primer → Грунт, Metal → Металлик, Air → Для аэрографа, Technical → Спецэффект, Medium/Thinner/Retarder/Flow improver/Cleaner/Putty/Filler/Restorer → Техническая, Ink/Inks/Dipping/Dip/Quickshade → Чернила, Pigment/Pigments → Спецэффект.

## MVP — этапы

### Этап 1. Каркас и ручной ввод
- [x] Репозиторий, структура, установка и запуск одной командой на Linux и Windows
- [x] Конфиг (порт, папка данных) с разумными значениями по умолчанию для каждой ОС — порт по умолчанию 8642
- [ ] Рецепты автозапуска: systemd (Linux), планировщик задач (Windows)
- [x] SQLite-схема: paint, storage, tag, paint_tag, tag_keyword; миграции через `PRAGMA user_version`
- [x] REST API: краски, хранилища, теги; поиск и фильтры
- [x] Справочник производителей: выбор из списка, добавление из формы краски, страница «Справочники» (производители + теги), фильтр по производителю; миграция старой базы без потери данных
- [x] Веб: список красок, карточка, добавление/редактирование вручную
- [x] Хранилища: создание, переименование, флаг «под рукой»
- [x] Теги: стартовый набор, редактирование, фильтры-плашки
- [x] Поиск по названию/производителю/коду
- [x] Фильтры: по хранилищу, по тегам, «под рукой», «нет в наличии»
- [x] Hex-плашка цвета в списке и карточке

### Этап 2. Хранилища и метки
- [x] Страница хранилища по ссылке `/storage/<id>` — список красок в нём
- [x] Ссылка для записи в NFC-метку (с адресом компьютера в сети) и кнопка «Копировать»
- [ ] QR-код для хранилища как запасной вариант
- [x] «Добавить в это хранилище» прямо со страницы хранилища
- [x] Перенос краски в другое хранилище (в т.ч. в «под рукой»)

### Этап 3. Распознавание по фото (веб)
- [x] Загрузка фото через штатную камеру телефона или из галереи (работает по http); на телефоне фото уменьшается до 1600 px перед отправкой
- [x] Штрихкод → поиск известной краски; новый штрихкод сохраняется вместе с краской или при «+1 банка»
- [x] OCR → строки текста кнопками, для названия куски — переключатели, склеиваются в порядке нажатия (повторное нажатие убирает); код и производитель — замена; название в две строки склеивается автоматически
- [x] Нечёткий поиск по уже занесённым краскам → до 3 кандидатов с кнопками «+1 банка» и «Открыть»
- [x] Автоподсказка тегов по словам с этикетки; производитель, название и код (Vallejo, Citadel, AK, Army Painter, Tamiya) определяются автоматически
- [x] Подтверждение: распознанное только заполняет поля формы, сохраняет пользователь
- [x] Если форма открыта со страницы хранилища — краска сразу ложится туда

### Этап 3б. Камера: фото или поток
- [x] Настройка на устройстве: «Фото» (приложение камеры, работает по http) или «Поток + фото»; на компьютере — только загрузка файла

- [x] Без HTTPS — подсказка, как включить флаг Chrome для адреса приложения
- [ ] Временный самоподписанный сертификат или подключение нормального — потом

## В планах (отложено)

- **Кириллица на этикетках** — стандартная модель RapidOCR читает только латиницу и цифры; можно подключить модель для кириллицы, если понадобится.
- **Фото этикетки в карточке краски** — сейчас фото используется только для распознавания и не сохраняется.

- **«Разобрать ящик»** — пачкой вернуть всё, что под рукой, по своим коробкам.
- **Потенциальная замена** — для нужной краски, которой нет, найти близкие по цвету среди своих (ΔE по hex), с учётом совпадения тегов; сначала из «под рукой», потом из коробок.
- **Список покупок** — из красок с количеством 0, выгрузка/отправка в бота.
- **Hex пипеткой с фото** — с выравниванием баланса белого по белой карточке, помечается как «примерный».
- **Узнавание по картинке** — маленькая модель-эмбеддер (CLIP в ONNX) для повторных банок без штрихкода.
- **Локальная vision-модель** для массовой заливки фото ряда банок (проверить скорость на Pi 5).
- **HTTPS** — самоподписанный сертификат, который приложение создаёт само, или подключение нормального; тогда поток с камеры и Web NFC заработают без флага Chrome.
- **Связка с Project Hub** — список красок для проекта покраски.
